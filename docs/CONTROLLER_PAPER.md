# Bybit controller paper runner

Запуск контроллера:

```bash
python scripts/run_bybit_controller.py
```

После успешного закрытия сделки контроллер обновляет отчёты по единому
JSONL-журналу:

- текстовый отчёт: `reports/trade_statistics.txt`;
- графический отчёт: `reports/trade_statistics.png`.

Если новая закрытая свеча отсутствует или журнал закрытых сделок не изменился,
существующие отчёты не перезаписываются.

Если предыдущая генерация завершилась ошибкой и TXT или PNG отсутствует,
следующий запуск без новой свечи пытается восстановить оба отчёта из
существующего JSONL-журнала. Торговый контур при восстановлении не запускается,
поэтому повторная запись или дубликат сделки не создаются.

Пути можно переопределить:

```bash
python scripts/run_bybit_controller.py \
  --statistics-report /path/to/trade-statistics.txt \
  --statistics-plot /path/to/trade-statistics.png
```

Пути по умолчанию вычисляются относительно корня проекта и не зависят от
текущего рабочего каталога процесса.

## Защита от одновременного запуска

Контроллер удерживает Linux advisory lock на протяжении всего торгового цикла,
включая генерацию отчётов. По умолчанию используется lock-файл
`state/bybit_controller.lock` относительно корня проекта. Путь можно изменить:

```bash
python scripts/run_bybit_controller.py \
  --lock-file /path/to/bybit-controller.lock
```

Если другой экземпляр уже работает, новый запуск завершается с кодом `2`.
Код `0` означает успешный запуск, код `1` — ошибку контроллера, отчётности или
lock-файла.

Lock-файл может существовать постоянно. Само наличие файла не означает, что
контроллер работает: защита основана на `fcntl.flock` открытого файлового
дескриптора. После аварийного завершения процесса операционная система
автоматически освобождает блокировку, поэтому оставшийся файл не мешает
следующему запуску.

При запуске через systemd unit/timer параллельный ручной запуск безопасно
отклоняется тем же механизмом.
